# Инструкция оператора

## Проверить Compose без запуска

Выполнять в WSL из корня репозитория. Нужны Bash, Docker Compose v2
(проверено на v2.35.1) и `jq`. Выберите окружение по [таблице в README](../README.md).

```bash
cd /opt/petar-deploy
bash scripts/check-compose.sh
```

Ожидаются три строки `Compose isolation checks passed`, по одной на окружение.
Скрипт выполняет `docker compose config`: не стартует контейнеры, не скачивает
образы, не создаёт каталоги данных и не запускает runner.

Чтобы вывести итоговый JSON только одного окружения, передайте `--render`
с именем `dev`, `rehearsal` или `production`, например:

```bash
bash scripts/check-compose.sh --render rehearsal |
  jq '{name, networks, services: (.services | map_values({ports, volumes}))}'
```

Сверьте имя проекта, имя сети, порты и источники томов с README. Без фильтра
JSON также содержит **тестовый** пароль и DSN. Скрипт берёт значения из
`env/<окружение>.env.example`, подставляет фиктивные образы/пути релиза и
не использует локальный `.env` или секреты оболочки. Этот результат нельзя
использовать для запуска. Не сохраняйте вывод с реальными секретами в Git.

Если команда не проходит, проверьте, что установлены Compose v2 и `jq` и
запускается именно конфигурация нужного окружения. При расхождении сравните
`compose.yaml`, dev override и выбранный env-пример с таблицей README; не
исправляйте ошибку подключением данных действующей установки.

## Что потребуется при запуске

В явном env-файле выбранного окружения задаются порты и каталоги; реальные
артефакты передаются через `APP_IMAGE`, `POSTGRES_IMAGE`, `DOKUWIKI_IMAGE`,
`POSTGRES_FILES_DIR` и `PLUGIN_DIR` (для dev часть указывает на checkout).
Нужен отдельный локальный `POSTGRES_PASSWORD`, содержащий только символы
`A–Z a–z 0–9 . _ ~ -`: значение используется и в PostgreSQL, и без
URL-кодирования в DSN. Env-файл с секретами держать вне Git. Перед запуском
оператор отдельно проверяет существование и права каталогов, порты и пути
до артефактов. См. [подготовку `deploy-001` и чистой wiki](release-001.md).

На хосте у runner всегда задавайте **обе** переменные: `SPOOL_DIR` и
`API_BASE_URL`. Без них скрипт Go-проекта может обратиться к рабочему spool
и API. Cron на этапе проверки Compose не включается.
